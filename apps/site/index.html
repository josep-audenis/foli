On pages

A web page scrolls forever. A document does not. It has a size, margins and a last line before the next page begins.

Pull on this one

Shorten the page and the text moves on. Narrow the margin and every line breaks again. Foli does this work as you type, measuring real lines in the browser.

Rules typesetters care about

A paragraph may break across pages at a line, never inside one. Widow control stops the last line from landing alone at the top of a page, and the first line from staying alone at the bottom. Keep with next holds a heading to the paragraph after it.

Switch a rule off and the page marks what it was preventing.

Word's rules, Word's model

Most documents people edit are Word documents. Foli reads a .docx into a model shaped like Word's own: paragraph styles, numbering, tables, pictures and runs with their formatting. What it does not model yet is kept and written back.

Made for review

Reviewers work the way they do in Word. Every insertion and deletion is recorded in its author's name, and each one can be accepted or rejected on its own. Comments sit beside the pages, with replies.

Long tables break between rows and repeat their header on the next page, so nothing is cut in half. Pictures keep their size and their place in the text.

An engine of its own

There is no ProseMirror, Tiptap or Lexical underneath. The model, transactions, view and layout are all Foli, so pages are part of the engine and never an effect drawn over a long scroll.

A document is not a long text box. It has pages, styles, numbering, reviewers and a file format older than most browsers. Foli treats all of that as the engine's job, so your product does not have to fake it.

FoliReview

Settle a draft, one change at a time.

Foli records insertions, deletions and formatting as people type. Show all markup, simple markup or none, then accept or reject each change. Comments and changes round-trip with Word.

FoliTables

Tables that know about pages.

A long table splits between rows and repeats its header rows on the next page. Merged cells, table styles and tracked row changes come with it, as Word models them.

Foli.docx

Open a .docx. Save it back. Lose nothing.

@folijs/docx writes only the parts the editor owns, keeps unchanged elements verbatim, and copies every other part of the package byte for byte.

FoliEngine

An engine of its own, from model to layout.

No ProseMirror, Tiptap, Lexical or Slate underneath. Because pagination is part of the engine, the cursor, selection and undo all know where pages begin.

FoliGetting started

One component, real pages.

FoliEditor brings the pages, a toolbar and a comments pane. Load a saved document with parseDocument, which validates it and migrates older versions. Save from onChange.

Prefer your own toolbar, or no React at all? The getting started guide covers both.

Try the editor

Editor.tsx
import { createDocument, parseDocument } from "@folijs/core";
import { type FoliChange, FoliEditor } from "@folijs/react";
import "@folijs/react/styles.css";

const saved = localStorage.getItem("doc");
const initial = saved
  ? parseDocument(JSON.parse(saved))
  : createDocument();

const save = (c: FoliChange) =>
  localStorage.setItem("doc", JSON.stringify(c.document));

export function Editor() {
  return (
    <FoliEditor initialContent={initial} onChange={save} />
  );
}

Where it stands.
