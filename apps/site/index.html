On pages

A web page scrolls forever. A document does not. It has a size, margins and a last line before the next page begins.

Pull on this one

Shorten the page and the text moves on. Narrow the margin and every line breaks again. Foli does this work as you type, measuring real lines in the browser.

Rules typesetters care about

A paragraph may break across pages at a line, never inside one. Widow control stops the last line from landing alone at the top of a page, and the first line from staying alone at the bottom. Keep with next holds a heading to the paragraph after it.

Switch a rule off and the page marks what it was preventing.

Word's rules, Word's model

Most documents people edit are Word documents. Foli reads a .docx into a model shaped like Word's own: paragraph styles, numbering, tables, pictures and runs with their formatting. What it does not model yet is kept and written back.

Made for review

Every insertion and deletion is recorded in its author's name, and each one can be accepted or rejected on its own. Comments sit beside the pages, with replies.

Long tables cross page breaks and repeat their header rows. Pictures keep their size and their place in the text.

An engine of its own

There is no ProseMirror, Tiptap or Lexical underneath. The model, transactions, view and layout are all Foli, so pages are part of the engine and never an effect drawn over a long scroll.

What you install

Four packages. The core holds the model and commands and runs anywhere, with no DOM. The view draws the pages and handles input. The React package adds the editor, a toolbar and the comments pane, and the docx package reads and writes Word files.

Documents are plain JSON, so they can live in your own database and travel through your own API. Older versions are migrated when they load.

Still to come

Headers, footers, footnotes and page numbers are kept when you save, but the editor does not show them yet. They are being built now.

FoliGetting started

One component, real pages.

FoliEditor brings the pages, a toolbar and a comments pane. Documents are plain JSON: save them from onChange, load them with parseDocument.

Your own toolbar, Next.js or no React at all? The getting started guide covers them.

npm i @folijs/react @folijs/core @folijs/docx
Editor.tsx
"use client";
import { createDocument } from "@folijs/core";
import { FoliEditor } from "@folijs/react";
import "@folijs/react/styles.css";

const initial = createDocument();

export function Editor() {
  return <FoliEditor initialContent={initial} />;
}
